# System Architecture

## Overview

The system consists of two main components communicating over two wireless channels:

1. **Anchors** (3x DWM3001CDK) — fixed UWB reference points at known positions
2. **Tag** (iPhone 16 Pro Max) — mobile device that computes its own position

**BLE** is used for control: discovery, connection, and exchanging NI configuration data.
**UWB** is used for ranging: high-precision distance measurement via Two-Way Ranging (TWR).

### Position Computation Pipeline

```
Distance updates (per anchor, ~6 Hz each)
         │
         ▼
PositioningViewModel (10 Hz timer)
         │
         ├── Collect latest distance from each ranging anchor
         ├── Apply calibration offset (from AnchorConfigStore)
         ├── Filter stale readings (> 2s old)
         │
         ▼
TrilaterationEngine.computePosition()  (or weighted variant)
         │
         ├── Match anchors to distances by ID
         ├── Require >= 3 matched pairs
         ├── Linear least-squares: subtract circle eq. 0 from others
         ├── Solve 2x2 normal equations: x = (A^T A)^{-1} A^T b
         │
         ▼
PositionFilter (moving average, window=5)
         │
         ▼
computedPosition  →  FloorPlanView (blue dot)
                 →  DataExportService (if recording)
```

## Trilateration Algorithm

### Linear Least-Squares

Given `n >= 3` anchors at positions `(x_i, y_i)` with measured distances `d_i`, the circle equations are:

```
(x - x_i)^2 + (y - y_i)^2 = d_i^2    for i = 1..n
```

Subtract equation 0 from equations 1..n to linearize:

```
2(x_1 - x_0)x + 2(y_1 - y_0)y = (d_0^2 - d_1^2) + (x_1^2 - x_0^2) + (y_1^2 - y_0^2)
```

This gives the system `Ax = b` where A is (n-1) x 2. Solve via normal equations:

```
x = (A^T A)^{-1} A^T b
```

### Weighted Variant

In weighted mode, rows are scaled by `w_i = 1/d_i^2` (closer anchors contribute more). This improves accuracy when distance noise scales with range.

### HDOP (Horizontal Dilution of Precision)

HDOP quantifies how anchor geometry amplifies range errors into position errors:

```
H = [h_x, h_y]  for each anchor (unit direction from tag to anchor)
Q = (H^T H)^{-1}
HDOP = sqrt(Q[0,0] + Q[1,1])
```

- HDOP < 2: good geometry
- HDOP 2-5: moderate
- HDOP > 5: poor (anchors nearly collinear)

## BLE GATT Protocol

### QNIS Service (Qorvo NI Service)

| Characteristic | UUID | Direction | Purpose |
|---------------|------|-----------|---------|
| Service | `2E938FD0-6A61-11ED-A1EB-0242AC120002` | — | Service identifier |
| RX | `2E93998A-6A61-11ED-A1EB-0242AC120002` | Phone → Anchor | Write shareable config |
| TX | `2E939AF2-6A61-11ED-A1EB-0242AC120002` | Anchor → Phone | Notify (ACD, status) |

### NI Message Format

Messages use a 1-byte message ID prefix:

| ID | Direction | Meaning |
|----|-----------|---------|
| `0x0A` | Phone → Anchor | Init request |
| `0x01` | Anchor → Phone | Accessory Configuration Data (38 bytes) |
| `0x0B` | Phone → Anchor | Configure + start (shareable config) |
| `0x02` | Anchor → Phone | UWB did start |
| `0x0C` | Phone → Anchor | Stop UWB |
| `0x03` | Anchor → Phone | UWB did stop |
